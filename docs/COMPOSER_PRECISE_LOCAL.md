# Local precise Composer editing

The additive editor is enabled by `NEXT_PUBLIC_COMPOSER_DIRECT_REGENERATE=true` in a development build. The existing GenerationPanel routes a tagged selection by `element_metadata.owning_family` and the `composer-taxonomy-v1` registry. Unsupported source versions and variants are visibly rejected. Untagged selections keep their existing handlers.

The supported slice is TEXT_BOX (rich_text, card, scenario_card, comparison_row, callout), METRICS (single, card, pill, total_band, shared_panel), TABLE (plain) and INFOGRAPHIC (timeline.alternating_milestones, process.connected_steps). Each field comes from an explicit typed editable-slot pointer in the saved owning-service request. It is never scraped from rendered HTML. Selecting another ID or source hash remounts the form with its saved values.

`/api/composer/regenerate` requires the local development flag, a NextAuth session, loopback access and a matching request origin. It reads the authoritative native element from local Layout. A POST applies only explicit string slot edits and an explicit variant selection, then renders through Text on 8505 or Illustrator on 8507. It checks the returned source, slot census, frame and HTML digest, then submits a full replacement with the old source hash to Layout on 8504. Layout validates before committing. The adapter verifies the replacement and every untouched element against readback. A rejected render preserves the old element; an uncertain transport outcome requires reconciliation rather than a blind retry.

After a successful commit the Builder remounts its actual viewer, discarding stale autosave timers, and selects the replacement through Layout's generic `selectTextBox` command (which selects every native collection). If another element was selected during the render, that current selection is retained instead. The existing Mode → Edit control enables infographic selection.

For this local review, `/builder?composer_presentation_id=<local UUID>` loads an existing local deck without a Director or database session. It only activates with the direct-regeneration flag. Automatic theme synchronization is disabled for this explicit local source so opening a measured deck does not repaint it. The app's analytics script is disabled under the same local flag. The development launcher supplies all public variables explicitly, uses a dummy local-only authentication secret, blocks outbound Node connections and disables remote font fetching. Presentation fonts inside the Layout iframe are unchanged.

The launcher and full environment inventory are maintained in the Composer worktree: `tools/round6_frontend_server.py` and `library/round6/frontend/public-env.json`. It serves the frontend on 3006, Layout on 8504 and keeps all other public service URLs on unreachable loopback. It never loads the protected original frontend checkout or production credentials.

## Production gateway handoff

Elementor is not called or modified. For production it would need to forward the exact accepted request (including structural `variant_id`, schema version, typed `editable_slots`, measured geometry and accepted assets), preserve the complete `element_metadata` and authoritative carrier, and return the owning service's normalized `render_request`, request hash, HTML hash and renderer identity. It must carry the expected old source hash and native element ID through an atomic Layout recreate, propagate capacity/conflict/validation errors without a fallback renderer, and return the replacement ID and authoritative readback. Authentication and authorization of that gateway remain a production integration decision. The local-only route cannot be enabled in a production build.

Checks: `node scripts/test-composer-atoms.cjs` exercises source hydration, explicit edits, response tampering, preserved fields, conflicts and transport ambiguity. The Composer report links the real browser edit proofs and network logs.
